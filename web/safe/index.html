Check your Safe's queue before you sign.

Paste a Safe multisig address. Rein reads every transaction waiting for signatures and checks each payee against what this Safe has actually paid before. It flags addresses dressed up as ones you pay (address poisoning), first payments to strangers, amounts far above the usual, and changes to who controls the Safe. It runs in your browser: nothing is signed, and no Rein server sees the address.

Get told before anyone signs

Rein can post to your team's Slack, Discord or Telegram the moment a risky payment is queued, once per transaction. It holds no key and can't sign or move anything.

With no server: a GitHub Action

Copy this file into any repository you own as .github/workflows/rein-safe.yml, then set the variable SAFE_ADDRESS and the secret REIN_WEBHOOK. It checks every 10 minutes.

What this does not say

      
    
        
  • It knows only what this Safe has paid in tokens, from public chain data. ETH paid out of a Safe isn't counted yet, so a usual ETH payee can show up as new.
    • 
        
  • A payee it flags may be fine: a new contractor is a first payment too. The flag says to confirm the address through another channel, not that it's an attack.
    • 
        
  • A payee it doesn't flag isn't vouched for. It checks addresses against this Safe's own history, not against scam lists or what a contract does.
    • 
      

    

  






  
Rein reads queued transactions from Safe's public service and the Safe's history from Blockscout. It's the same code as npx rein-wallet safe; read it at github.com/let-the-dreamers-rise/rein. MIT.
